# Cells 资源存储与锁

导出根是目录访问能力，不代表整个目录的独占所有权。创建、遍历、rename、unlink 复用 Linux 的路径解析与原子系统调用；应用只协调一次操作真正涉及的资源，不给所有祖先目录加读锁。

| 资源 | 正文存储 | 必要协调 |
| --- | --- | --- |
| 尚未绑定的宿主草稿 | `harness-sessions/<draft-key-hash>.sqlite` | 对应 namespace；首次绑定迁移后发布路由 |
| 原生会话的宿主元数据、队列及恢复回执 | `harness-sessions/<session-key-hash>.sqlite` | `(project, owner, profile, session)`；同会话多 namespace 共享事务 |
| 原生执行恢复责任 | `.cells/executions/<scope-hash>/sessions/<session-hash>.sqlite` | 对应会话；request 路由以独立小文件原子发布 |
| 当前 epoch 的原生操作回执 | 私有临时目录内按 scope/request 分片 | 对应操作；unknown 不重放 |
| 通道上下文、消息、交换及回执 | `channel-scopes/<project-scope-hash>.sqlite` | 对应通道；工作目录的活动通道交接需协调同一目录 |
| MCP 配置 | `channel-scopes/<owner-hash>.sqlite` | 对应认证身份 |
| 文件自定义属性 | `.nestos/metadata-<stable-identity>.sqlite` | 对应文件的 SQLite 事务；保留稳定身份 |
| SeqFile | 文件本身的 SQLite | 取得写事务后复核条件版本，提交后取得新版本 |
| 普通文件正文 | 文件本身及同目录随机暂存文件 | 创建用 `RENAME_NOREPLACE`；条件替换短暂协调目标 inode，重验路径身份及版本 |
| 上传恢复责任 | `.itookit-upload-state/uploads.sqlite` 小型索引 | 短索引事务及每个随机暂存身份的恢复租约；不锁整个导出 |

节点保留小型发现索引：`harness-index` 只保存 namespace 路由与绑定，`channel-index.sqlite` 只保存授权、路由及小型生命周期信息；文件的 `meta.sqlite` 保存路径、稳定身份与 scope 路由。正文不因不同会话或文件而共用这些索引的写事务。索引及连接注册表的短临界区仍需互斥，不能持有它们等待原生历史、网络或正文 I/O。

`KeyedLocks` 提供可截止、可取消的异步资源协调；`SyncKeyedLocks` 用于同步资源事务。`SqliteShards` 将连接与事务锁绑定到一个物理数据库，连接注册表锁在打开数据库前释放。`PathLocks` 只锁显式声明的目标；多目标排序去重。同一 profile 的删除/归档只锁 native adapter 声明的真实会话树，不排斥无关树，并在取得锁后重新核对资源集合。

节点 FileGate 只登记关闭排空，业务入口不再取得节点独占许可。项目配置、执行环境修改、重挂载和移除取得对应项目的生命周期独占许可；文件读写、流式响应、已接纳命令与原生 turn 持有该项目的共享许可。原生 turn 引用其他项目上下文时，也持有这些实际依赖项目的许可。无关项目可以继续工作；同项目占用返回明确的 EBUSY，并在日志标明资源身份和实际持有者。未知清理只封闭涉及的项目，未绑定项目的旧进程入口仍保留节点级未知所有权保护。

目录同步仅持有项目共享许可，修改按 bindingId 串行，等待可取消且最长 30 秒；状态和目录读取不占绑定修改锁。不同绑定可并行，创建绑定时在目录索引的同一次原子提交中复核重复与物理路径重叠。注册/重挂载只协调认证身份、alias 和目标路径所代表的注册资源，不再持有覆盖所有项目及磁盘准备的服务级互斥。节点 ID 命名空间的短临界区只负责预留可读 ID，目录准备与元数据迁移在锁外完成；完成或失败后释放预留。

`KeyedGates` 的注册表不覆盖资源工作；回收闲置项时检查实际 Owned permit 和运行时句柄，活跃或清理未知的项目不能被回收成另一把锁。后台阻塞任务、上传提交及流式正文自行持有项目许可，HTTP 等待者结束不会提前解除授权边界。项目发现 catalog 仍由单个所有者维护 `projects.json` 文件；该文件内的 CAS、ID/目录唯一性及同步绑定索引提交由文件自身的短事务协调。

## 草稿与会话责任

NestOS 分配并保存稳定草稿身份，首次发送时才创建或绑定 Cells 原生会话；只读呈现不创建会话。llm-ui 负责呈现与交互，宿主适配器封装原生绑定与恢复。Cells 接管执行队列后，宿主不再将旧快照里的 queue 整体写回。原生已接纳、宿主回执持久化失败时保持 unknown，继续查询原操作，不生成新身份或自动重发。接纳成功后只清理匹配此次提交的草稿；发送期间新编辑的内容继续保留。

## 兼容与失败

旧 `harness-client-state.sqlite`、`session-channels.sqlite` 和 scope 级 execution 数据库保留不删，按 namespace、scope 或 session 首次访问时事务导入。导入记录与数据同事务提交；会话绑定先复制正文，再发布小型路由。路由发布失败后，重试重新复制最新草稿，不把旧复制结果当作完成。文件属性旧 inline 数据读取兼容，写入后正文进入稳定身份文件。目录 scope 迁移只协调涉及的属性文件，并复核源身份集合；路由已变化的迟到写者得到明确冲突。

SQLite 自身仍有页锁和写事务；文件 inode 的 advisory lock 只能约束合作写者。非合作 Bash、IDE、Git 或其他客户端的并发写入没有跨入口事务保证。文件指纹用于检测观察到的外部变化，不能将超时、连接失败或 native 子命令退出统一归因于锁。

慢存储/失败记录 `storage.resource.completed`（资源摘要、阶段、具体错误码、耗时），会话等待记录 `harness.session.lock`。既有 HTTP/request trace 负责关联请求，不记录正文、命令参数或凭据。通道 SSE 订阅不占文件 watcher 的 16 个配额，仍受 SSE 自身连接/topic 限额约束。

## 验证

回归覆盖独立资源并行、同会话串行及取消、删除子树范围、旧数据导入、绑定路由发布失败后的最新草稿、跨实例属性合并、同文件条件替换单一成功者、多可写导出及活跃上传恢复。浏览器草稿首次发送样本使用真实宿主和 llm-ui，原生 Cells 适配为受控测试端；此样本不代替部署后的线上完整页面性能验收。

2026-11-14 工作树验证：完整 `cargo test` 开启 `CELLS_PROCESS_TEST=1` 与 `CELLS_PROJECT_TEST=1` 通过，原生模型使用测试驱动夹具；真实进程沙箱、取消、恢复及资源并发均包含在内。NestOS 相关 60 项与 cells-driver 相关 106 项通过；工作区类型、架构、文档检查通过。性能回归 core 60 项、transport 31 项通过。Chrome headless 固定 1 草稿、1 已有会话、1 turn、无后台负载：冷打开草稿 73.8 ms/2 次逻辑 API；热首次发送 102.4 ms/22 次；热打开已有会话 17.8 ms/6 次，HTTP 请求数均为 0（注入原生接口）。临时进程清理确认；未部署或重启线上服务。
