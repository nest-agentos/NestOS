# 性能回归与验收

默认门槛按**一次用户操作**计：从点击到目标页面可操作，耗时严格小于 5000 ms，逻辑 API 调用严格少于 30 次。两项必须同时满足；5000 ms 或 30 次均失败。不能把每个 API 分别低于五秒当作整条链路达标。

## 固定回归入口

```bash
pnpm test:performance
pnpm test:performance core
pnpm test:performance transport ui
```

入口串行执行对应测试，任一步失败即返回非零；所有临时驱动在 temporary-process 有界作用域内执行，确认清理后才输出成功。已有全量 `pnpm test` 仍包含这些文件；定向入口减少每次修改的验证成本。

- budget：严格时间/次数边界、批量 RPC 计数、缺失指标、未完成操作与基线退化的失败测试。
- core：直达会话不枚举无关会话/历史，独立准备并行且仅读一次，业务 Effect 未完成时摘要仍可冷读；有界目录预览、原生会话身份与状态读取契约。
- transport：批次上限和慢能力隔离，重复读取不重算无关快照，流式内容增量和通知有界合并。
- ui：真实 LocalFS 的 A→B→A、100 轮历史、首次与重复加载的读取预算，导航聚合读取及隐藏窗口行为。

稳定的读取数、扫描范围、重复绑定数是硬断言；不能只打印统计。毫秒预算与调用次数分别检查，不能互相抵消。不得通过删测试、扩大上限、强制缓存或忽略失败来宣称优化成功。

## 真实 HTTP 会话 API 检查

复用已有 profile-session-switch，不建立第二套协议或存储接口：

```bash
pnpm performance:session --connect https://SERVER:2000 \
  --client-cert /private/client.crt --client-key /private/client.key \
  --ca-cert /private/ca.crt --session SESSION_ID \
  --samples 3 --dataset FIXED_DATASET --out /private/current.json
```

在相同会话、数据规模、机器和负载下，使用 `--baseline /private/previous.json` 比较。基线自身必须达标且场景、数据集匹配；时间增加超过 20% 加 50 ms 判为退化，逻辑 API 次数增加也判失败，不能用变快掩盖调用增加。基线只读，工具不会自动覆盖或批准新的基线。每个样本都受绝对门槛约束，不能用平均值隐藏慢样本。

计时从建立该客户端开始，到会话准备及激活完成为止，清理之前冻结。计数来自实际 HTTP 客户端发送边界：批量 queries/bindings 中每个调用分别计数；bootstrap、单调用及协议读取也计数。另行记录 HTTP 请求数，不以合并请求来缩小逻辑调用量。错误请求计入次数，未知格式、缺失指标、未完成或清理失败不能通过。报告不包含请求正文、会话内容或证书材料。

**该命令是 API 就绪检查，不是完整浏览器验收。** 它不包含页面 JS/CSS 加载、布局、渲染和侧栏之外的应用流程；不能把它通过解释为用户点击到可操作已经低于五秒。完整页面仍需从点击开始测到目标身份正确、历史加载完成、输入可用，并统计这一整个区间的 API。缺少这个证据时，报告“页面性能未验证”。缓存、后台任务、远程 Cells 与冷/热状态必须注明，不能拿热缓存样本证明冷打开。

## 本次基线与已发现缺口

2026-11-06 的实际审计曾出现工作台准备 14482 ms、激活 9535 ms、重复打开 10130 ms，以及会话状态读取 85159 ms。这些是失败样本，功能测试全绿不能替代修复后的同口径复测。真实链路中 SQLite/SeqFile 的等待和读取量仍须按复现补足断言，不从接口总耗时猜测唯一瓶颈。

涉及打开、状态投影、订阅、批次、存储或恢复的修改：完成前运行相关性能套件及对应真实场景，记录版本、固定数据规模、冷/热状态、耗时和 API 次数；未达标须明确保留未完成状态。仅改文案等不触及该链路的变更不重跑全量性能矩阵。
