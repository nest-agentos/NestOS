# 模块化 MCP Skills 设计草案

状态：部分实现，Cells 提供静态清单的会话作用域协议；动态内容、宿主加载及更新恢复尚未完成。规范基线为 [ext-skills beta](https://github.com/modelcontextprotocol/ext-skills/blob/c0705f9071caa539eeb2c9f5f2f77ac16b048ca6/specification/beta/skills.mdx)，提交 `c0705f9071caa539eeb2c9f5f2f77ac16b048ca6`；依赖 MCP `2026-07-28` 和 Agent Skills 格式。不可将本文当作全链路互通声明。

## 现状与边界

Cells 会话端点按 token 绑定冻结作用域，现代协议声明 tools、resources 和 Skills；旧协议保留 initialize 和五个工具。Kanban 可按决策模块版本、阶段及宿主显式授权生成冻结投影；软件开发模块通过通用提供者契约接入，授权前不会读取其文件。Cells 的静态清单读取按投影、项目 revision 和挂载授权，并核对原始字节。宿主默认会话来源通过持久原生上下文和项目通道读取授权元数据，绑定真实节点、项目、工作区、原生会话及作用域；token 留在 Cells。会话控件可提交持久批准任务，并按会话、节点、作用域、URI、清单摘要及当前能力作用域窗口核对实际交互回执；作用域重建后旧窗口失效，源消费者可据回执读取经验证内容。Skill 面板可请求批准并附着持久交互任务。模型上下文的生效窗口及执行门禁尚未接到激活链，远端条目仍明确拒绝加载。普通资源读取不等于 Skill 加载。核心不得按业务名称分支。

## 贡献与投影

模块贡献应包含稳定模块 ID、版本、来源身份、技能 URI、适用阶段和授权约束，以及不可变的文件清单或明确的动态声明。当前静态清单投影同时冻结项目 ID、revision、挂载标识、每项显式相对路径及完整 frontmatter；来源项目须与任务项目一致，相对路径不能穿越。动态声明尚未实现。由受信任宿主验证贡献、选择任务所关联的模块及阶段，并将授权结果绑定到具体会话作用域。相同名称的不同来源不可合并；版本和来源变更均须形成新投影。快照保留现有任务、身份、授权及回执数据，Skill 指导不替代它们。URI、路径和文件必须规范化，拒绝路径穿越、重复条目、外部链接及超出已授权范围的文件。

## Cells 服务端

每个请求通过已绑定 token 查找该作用域的投影；list、get、read 均独立授权，不以列表隐藏代替权限检查。现代发现同时声明 resources 与 `io.modelcontextprotocol/skills`；未完整实现目录读取时不声明 `directoryRead`。list 的每个条目保持原子完整，稳定分页游标绑定投影版本，缓存作用域为 private；get 对所有已授权 URI 直接查找，未知或未授权 URI 返回规范的 `-32602`，内部故障返回 `-32603`。清单包含所有文件和原始字节的 SHA-256、字节数，保留全部 YAML frontmatter 字段。动态内容标为 `dynamic`，不可伪造稳定清单。不得把不同会话的投影或缓存混用。

## 宿主加载与更新

以宿主分配的服务器身份加 Skill URI 为键。先发现能力，再按需 list 或直接 get；加载时取得用户所需授权并绑定完整清单，按需从同一服务器读取文件，校验原始字节长度、摘要和完整 frontmatter。读取不在持有清单中的文件、清单变化或校验失败均停止使用，刷新元数据并在需要时重新确认。支持文件仅在引用时读取；嵌套 Skill 作为普通文件读取不构成激活，激活须独立授权。动态 Skill 不能沿用永久内容授权，可拒绝加载。远端内容标记来源，不能获得隐式代码执行或扩大工具权限；跨服务器读取须逐次授权。磁盘缓存须隔离本地 Skill 搜索路径并保持来源，读取时验证或保证不可变。

模块更新只向受影响会话登记待处理版本，在下一轮或安全节点校验并记录采用版本或明确失败；已进入模型上下文的旧内容不会因通知自动消失。需要替换时重新建立可证明的新上下文，或保留旧版本并报告需要新会话。不得静默修改已确认目标、授权、操作身份或回执；需要调整时使用现有正式确认链。恢复时重建来源、持有清单与版本，验证缓存和授权，不能把通知当作采用回执。

## 兼容与验收

Codex 的 [OpenAI 文档](https://developers.openai.com/plugins/concepts/skills) 描述本地/插件 Skills 和 MCP 工具，并未证明它实现本扩展；不能据此声称标准互通。Claude Code 和现有驱动的扩展支持亦需以可用版本的实测为准。旧客户端继续使用现有会话工具；兼容桥必须经过同等来源、授权与内容校验，不能绕过标准宿主安全要求。未实现或不可用的客户端必须明确列为未验证。

验收覆盖关联与非关联模块、逐 URI 越权、分页与缓存、文件 URI、完整 frontmatter、动态与嵌套、清单和字节不一致、版本切换、旧上下文、恢复、身份与回执不变、旧客户端和真实支持客户端的端到端路径。涉及打开、订阅或状态读取的实现还须按性能规范记录冷/热条件、数据规模、版本、逻辑调用、HTTP 与底层读取，并复测真实页面；不能以跳过代替通过。
