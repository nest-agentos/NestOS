# 时间语义与显示

NestOS 与 Cells 内部使用 UTC 时间点；浏览器仅在展示和表单输入边界转换为本地时区。时区转换不改写历史数据、资源身份、会话状态或任务结果。

## 数据与接口

| 语义 | 数据形式 | 规则 |
| --- | --- | --- |
| 绝对时间点 | Unix 毫秒 `number` | 如 `createdAt`、`updatedAt`、`at`、`observedAt`、`resetsAt`、`timeMs`；与时区无关，不存本地钟面值 |
| 文本时间点 | ISO 8601 UTC `string` | 新写入和 API 生成文本使用 `toISOString()`，带 `Z`；外部带偏移时间可解析为同一时间点，不能删除偏移后重解析 |
| 外部 Unix 秒 | 外部契约声明的 `number` | 在适配器边界转换一次为毫秒；禁止按数值大小猜单位或再次乘 1000 |
| 时长、超时、退避 | 毫秒 `number` | 如 `durationMs`、`timeoutMs`；不做时区换算；本机性能测量继续使用单调时钟 |
| 日历日期、全天事件 | `YYYY-MM-DD` | 日期不是 UTC 午夜时间点；保留原日期，结束日期继续遵循排他边界 |
| 周期计划的本地时间 | 钟面值及明确 IANA 时区 | 计算触发时间后得到 UTC 时间点；不把“每天 9 点”永久转换为固定 UTC 小时 |
| 无时区的外部文本 | 原始文本 | “7:31 AM”不能作为准确时间点；没有来源时区时不生成恢复倒计时，不按机器默认时区猜测 |

既有 API 的字段名、毫秒单位与持久格式保持兼容。带偏移的历史 ISO 时间仍可读取；不对用户文件、标题和历史事件批量重写。新默认文件标题使用文件系统安全的 UTC 文本并保留 `Z`。

## 共享显示边界

`libraries/ui-common/src/time-format.ts` 提供唯一的 UI 时间转换实现：

- `formatDateTime`：绝对时间，按浏览器本地时区显示日期、时间和实际 UTC 偏移。
- `formatClockTime`：紧凑钟面展示，同样显示实际偏移，包括夏令时变化。
- `formatCalendarDate`：日历标签，保留日期语义，不把标签解释为另一个时间点。
- `getDisplayTimeZone`：读取当前浏览器的 IANA 时区，不依赖 NestOS/Cells 的操作系统时区，不设置全局宿主时区。
- `localDateTimeInput` / `parseLocalDateTimeInput`：本地表单与 UTC 毫秒互转。非法日期、夏令时不存在时间和重复时间分别报告明确错误，不静默偏移或任选一个结果。
- `setTimePresentation`：可见内容使用同一格式化器，HTML `datetime` 继续使用带 `Z` 的 UTC 文本。

格式化器缓存有界；页面渲染不增加 RPC。相对时间、倒计时与耗时仍表达时长；需要绝对时间时复用上述工具。数字数量、货币和文件大小的本地化格式不属于时间转换。

## 已接入的数据与功能

| 模块 | 接入范围 |
| --- | --- |
| 看板 | 决策列表与详情、任务与评论、执行观察、操作请求、豁免记录、资源处理时间、截止时间表单 |
| 会话与 Flow | 历史消息、提示导航、发送队列、运行清单、原生会话观察、写锁、额度重置时间 |
| 文件与编辑 | 文件列表、内容时间、备份、附件、快照与学习记录 |
| 设置与诊断 | 诊断事件、扫描历史、工具包执行、连接检查、Cells 采样时间 |
| 邮件与日历 | 邮件时间、日历归档时间、定时事件；全天事件和日期标签保留各自语义 |
| Cells | JSONL 的 `time` 固定为 UTC `Z`，`timeMs` 表示相同时间点；新日志文件名以 `Z` 标识 UTC |

NestOS 日志与 API 原有的 `Date.now()` 毫秒及 `toISOString()` 已符合约定，无需改变操作系统时区。Cells 内部日志直接使用 UTC，而非依赖进程运行机器的本地时区。日志读取、界面和 API 不通过解析用户消息正文推断时间。

## 验证

共享工具覆盖 UTC、上海、纽约对同一时间点的显示、本地表单往返、夏令时偏移以及重复/不存在时间。Cells 回归核对 `time` 的 `Z` 格式与 `timeMs` 一致。修改打开/状态链路时仍遵守 [性能回归门槛](performance-regression.md)，不得靠放宽调用数或耗时门槛通过。
